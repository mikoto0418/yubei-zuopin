> 用途：供在工作站全量执行开发。本文件完整记录了需求、约束、验收标准与五套系统规格，
> 可据此 clone 开源二开 或 自写完整版，最终交付 5 个"功能完整、可部署、可测试"的学生作品级 Web 系统。

## 0. 结论摘要（先读这个）

要交付 5 个**风格各不相同**、**各有真实内核**、且**各自不同 AI 特色功能**的学生作品级 Web 系统。每套都必须具备：

- 真实业务内核（非纯娱乐，有实际使用价值）
- 前后端分离 + SQLite 持久化
- **账号系统**（普通用户 + 管理员两种角色）
- **Admin 后台 + 数据分析仪表盘**（各套图表主题不同）
- **至少一个 AI 特色创新点**（数字人 / 音频输出 / 语音交互 / 图片识别等）
- 代码**功能完整、可部署、可测试**（非最小骨架）

**完整度判定**：作品级 · 纯功能 + 测试 + 部署脚本（见 §3 验收清单，达人评审以此为准）。

**实现方式**：混合 —— 优先按领域找 GitHub 高质量开源项目 clone 做基底再二开；找不到合适开源则自写完整版。

## 1. 总目标

面向"学生作品/毕设/演示"场景，批量产出 5 个可运行、可演示、可答辩的完整全栈 Web 系统。
每个系统既是**功能完整的产品**，又要有**差异化卖点**（外观 × AI 能力 × 技术栈），用来体现工作量与多样性。

## 2. 五套系统共同约束（所有项目必须满足）

### 2.1 架构
- **前后端分离**；后端提供 REST API，前端通过 fetch/XHR 调 API。
- **数据库统一 SQLite**，本地文件持久化；建库/建表/种子数据由启动或脚本自动完成。
- 后端只用轻量框架，**禁止** Django 等重型框架：
  - Python 后端 → Flask
  - Node 后端 → Express
- 前端框架按差异化分配：React / Vue3 / 原生（三选一，见各套规格）。可配 Vite 构建。

### 2.2 账号系统与权限
- 注册 / 登录 / 退出；密码哈希存储（如 bcrypt / werkzeug）。
- 登录态用 JWT；提供认证中间件与 `admin` 角色 RBAC。
- 普通用户访问 Admin 接口/页面必须返回 403，并被前端拦截。
- 每套内置 seed 脚本，创建默认管理员 + 若干演示用户及演示业务数据（让仪表盘"开箱有图"）。

### 2.3 Admin 后台 + 数据仪表盘
- 仅管理员可进入；用 ECharts 或 Chart.js 绘制**至少 3~4 类**数据分析图表 + 统计卡片。
- 图表数据来自真实接口，而非写死。
- 各套图表配色/主题必须与自身前端风格一致。

### 2.4 AI 特色功能（真实实现，拒绝占位）
- 每套至少一个可用的 AI 功能点（见各套）。
- **统一接入约定**：AI 走后端 AI 接口 → 读取环境变量 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`（OpenAI chat completions 兼容）；配置了 Key 就走真实大模型，未配置则用**内置本地规则引擎**保底输出，保证离线也能演示。
- 语音类功能用浏览器原生 Web Speech API（`speechSynthesis` 合成 / `SpeechRecognition` 识别），仅在 Chrome/Edge 生效，需做"不支持时降级提示"。

### 2.5 差异化（确保 5 套互不雷同）
三要素**全部互不相同**：
- 前端风格（5 种）✓
- AI 能力（5 种）✓
- 前后端技术栈组合（Flask/Express × React/Vue/原生）合理错开 ✓

## 3. 完整度验收标准（每套系统评审以此为准）

考核判定为 **作品级 · 功能完整 + 可部署 + 可测试**。

### 3.1 业务功能（对应各自内核）
- 核心业务模块做到真实可用：CRUD 完备、字段建模完整、业务状态机/联动闭环成立。
- 关联数据完整（如：下单→成交状态流转；测评→分级→风险预警联动；做题→正确率→掌握度）。
- 数据库：外键/约束、索引合理，含可复现的 seed。

### 3.2 前端完整
- 页面齐全：**列表 / 详情 / 新增 / 编辑 / 删除 / 空态 / 加载态 / 错误态 / 分页 / 搜索 / 筛选**。
- 表单校验（前后端双重）、登录态守卫、路由守卫、403/404 页、页面标题与加载反馈完整。
- UI 达到"作品级"观感：不是裸奔 demo 样式，主题自成一体。

### 3.3 后端完整
- 统一响应结构（`{code, data, message}` 或类似）、参数校验、全局异常处理、鉴权 & RBAC。
- 列表接口支持分页/搜索/筛选；写接口校验输入。
- 全部能力必须通过**真实 HTTP 请求验证**通过，不是摆设。

### 3.4 可测试
- 后端单元/接口测试覆盖**核心链路**（注册登录、权限 403、关键 CRUD、AI 保底输出）。可用 pytest / node:test / jest / vitest。
- 测试可一键运行，README 写明命令。

### 3.5 可部署
- 每个项目提供**一键启动**（脚本或 Makefile）与**自助安装说明**（装依赖→配 .env→seed→启动）。
- 后端能托管前端构建产物（单端口部署）为**可选加分项**；至少要有明确的前后端启动命令。
- README 完整：项目介绍 / 功能 / 技术栈 / 目录结构 / 启动 / 测试 / 账号 / AI 配置 / 截图占位。

### 3.6 工程整洁
- `.gitignore`（node_modules、dist、*.db、.env、缓存/日志）。
- `SECRET_KEY`、`LLM_API_KEY` 等敏感项走 `.env` + `.env.example`，绝不硬编码进源码。
- 中文界面文案与中文 README。

## 4. 五套系统详细规格

### 4.1 MindCare · AI 心理健康陪护系统
- **内核**：学生压力/心理情绪的日常陪伴工具。
- **技术栈**：Flask + SQLite + JWT；React 18 + Vite + ECharts。端口 4101。
- **前端风格**：毛玻璃拟态（Glassmorphism）——柔和渐变背景 + 雾面卡片 + 半透明 + 高斯模糊 + 柔和圆角与投影，色调雾紫/粉蓝，营造治愈感。
- **业务模块**：
  1. 情绪日志：每日心情评分(1-10) + 情绪标签 + 备注，历史列表，防重复记录当日。
  2. 心理测评：Zung 抑郁量表(SDS) 20 题自评，正向/反向计分，换算标准分并分级（正常/轻度/中度/重度），历史记录。
  3. AI 陪护对话：多轮情感对话，支持 🔊 朗读回复。
  4. 冥想放松：选时长 → 播放 TTS 语音引导 (speechSynthesis，中文) + 呼吸动画 + 倒计时，结束自动记录时长。
- **数据表**（至少）：users / mood_entries / assessments / chat_history / meditation_sessions。
- **Admin 仪表盘**：情绪均值走势(折线)、情绪标签分布(饼)、测评水平分布(饼)、每日活跃写情绪人数(柱)、**风险预警名单**（最近一次测评非"正常"的用户，标红）。
- **账号**：`admin/admin123`，演示 `xiaolan/xiaolan123`。
- AI 落点：情感对话（LLM/保底）+ TTS 语音引导。

### 4.2 ScholarBoard · 学生智能工作台
- **内核**：学生日常学习/求职的"一站式创作与管理"工具。
- **技术栈**：Express + better-sqlite3 + JWT；Vue3 + Vite + ECharts。端口 4102。
- **前端风格**：编辑排版/杂志极简生产力风——暖白/墨水黑 + 单一强调色（珊瑚橙或克莱因蓝），大号衬线标题、讲究字距留白，像精致杂志编辑部。
- **业务模块**：
  1. 笔记管理：增删改查、标签、收藏、搜索。
  2. 简历工作台：多份简历草稿（岗位意向/技能/经历 JSON），AI 一键盘润色。
  3. 任务板：优先级/截止/按项目分组/标记完成。
  4. 个人中心：昵称、头像。
- **数据表**：users / notes / resumes / tasks（+ 可选 projects）。
- **Admin 仪表盘**：用户数、任务完成率、笔记创作趋势、活跃用户 Top。
- **账号**：`admin/admin123`；演示 `alice/bob/carol`（密码 123456）。
- **AI 落点**：AI 润色（LLM/保底）+ 语音转文字记笔记（SpeechRecognition）+ 语音朗读（speechSynthesis）。

### 4.3 EduPulse · AI 学习分析助手
- **内核**：把学习笔记/练习沉淀成"掌握度",辅助定位薄弱点。
- **技术栈**：Flask + SQLite；React 18 + Vite + ECharts。端口 4103。
- **前端风格**：Cyberpunk 霓虹 + 数据驾驶舱——深色底 + 霓虹紫/青/品红发光 + 扫描网格背景 + 发光图表。

  2. 题库练习：按知识点抽题作答、自动判定、记录对错。
  3. 学习记录：录入各科学时时长。
  4. 个人学习汇总：正确率/掌握度/时长。
- **数据表**：users / notes / quizzes / quiz_records / study_sessions。
- **Admin 仪表盘**：各科学习时长占比(饼)、知识点掌握度(雷达/热力)、正确率趋势(折线)、每日时长(柱)、用户活跃排行。

### 4.4 HiveMarket · 校园二手交易平台

- **内核**：考研/四六级/考公的"目标拆解 → 计划 → 进度 → 正确率 → 预测"备考闭环。

  1. 目标管理：各科目目标分数与权重，实时显示"还差 X 分"。
  2. 每日计划 + 番茄学习记录：今日计划、勾选完成、录入时长。

## 5. 工程与交付要求（每套统一）

- **目录**：每套 `backend/`（或 `server/`）+ `frontend/` + `README.md` + `.gitignore`。
- **依赖**：Python 用 `requirements.txt` + venv；Node 用 `package.json` 锁定版本。
- **配置**：`.env.example` 说明 `SECRET_KEY`、`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`PORT`。
- **种子**：提供 seed 脚本（管理员 + 演示数据），首次启动可自动执行。
- **测试**：核心链路测试存在的命令，README 注明。
- **启动**：README 给出简单几步跑起来（前后端分离模式，另给单端口部署加分项）。
- **端口规划**（唯一样例，可换但需全局唯一）：4101 / 4102 / 4103 / 4104 / 4105。
  ⚠️ 注意：某些本机会被软件占用端口（例如 QQ 常占 127.0.0.1:400x），交付时避免使用易冲突的低位端口，建议固定用 41xx 段。

## 6. AI 接入统一约定

1. 前端调用本套后端 AI 接口；后端负责拼 prompt、调用外部模型或本地保底。
2. 外部模型用 OpenAI 兼容协议：`POST {LLM_BASE_URL}/chat/completions`，模型名 `{LLM_MODEL}`，鉴权 `Authorization: Bearer {LLM_API_KEY}`。
3. **未配置 `LLM_API_KEY` 时必须自动降级为本地规则输出**（关键词匹配/模板），保证离线演示不报错；响应中可用字段标注来源（如 `source: local` / `source: llm`）。
4. 语音合成/识别用 `window.speechSynthesis` / `window.SpeechRecognition`，只在点击触发的用户手势后调用，避免浏览器自动播放限制。

## 7. 建议执行流程（在工作站按序推进）

1. **选型**（每套）：按领域搜索 GitHub MIT/宽松许可、较高 star、技术栈匹配的项目，评估是否能作为基底复用核心建模/页面；可 clone 二开。若 2~3 个候选都不合适，则自写完整版。
2. **骨架**：按 §2 统一架构，先搭一套完整基线（账号 + Admin + 仪表盘 + AI 约定），其余四套复刻该架构思路但换技术栈/风格。
3. **深化**：逐套按 §4 规格补全业务模块，并过 §3 验收清单。
4. **测试**：写核心链路测试并运行通过。
5. **部署验证**：按 README 一键启动，前后端联调，网页实际走通注册→核心流程→Admin 仪表盘→权限 403。
6. **交付**：每套提交 README（含启动/测试/AI 配置/截图占位）。
